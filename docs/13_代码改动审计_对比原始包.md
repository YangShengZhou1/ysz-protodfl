> 目的：把「从学生交接包到现在的代码」逐文件说清楚，判断有没有改到会让实验数字失真的地方。
> 审计时间：2026-11-04。可重跑：`python work/ProToDFL/scripts/diff_vs_original.py --original 'DisPFL-master-代码包' --current 'work/ProToDFL'`。

## 0. 结论先说

| 判断 | 内容 |
|---|---|
| 改了多少 | **5 个文件被改**、**0 个文件被删**、新增 28 个（其中 26 个是 `scripts/` 工具，不参与训练） |
| 有没有改动影响组内对照结论 | **没有**。all/base 两条分支共享同一初始模型、同一数据划分、同一邻居、同一权重，只差「是否平均分类头」；配对检查里 base 参数最大差 0.0 |
| 能不能说「复现了原论文数字」 | **不能**。数据划分算法、验证集切分、2-hop 候选语义、邻居数上限四处都变了，绝对数字与原始包/旧论文不可比 |

| 最需要写进论文的一句话 | 「结果基于本工作副本的重新实现，配置见 RUN-xxx，与原包默认配置不可逐点对比」 |

## 1. 审计口径

- 只比文本文件（`.py/.sh/.md/.json/.yaml/.txt/.csv`），跳过 `outputs/`、`datasets/`、`__pycache__`。
- 用 SHA-256 判断「是否变动」，用 unified diff 判断「变了什么」。
- 分类沿用项目约定：环境适配 / 缺陷修复 / 参考实现调整 / 新方法实验。

## 3. 会改变实验数字的五处实质改动

### 3.1 Dirichlet 划分重写（`_allocate_by_priors`）

原包 `dir` 分支：按 `clnt_data_list` 逐客户端、按类先验从各类池里**递减取样本**，某类取完后 `continue` 反复重抽。问题是：

- 客户端先验与类池容量不匹配时，理论上会**死循环**（所有剩余客户端都只剩已抽空的类）；
- 抽样顺序固定（每类从列表尾往前取），划分结果高度依赖遍历顺序；
- 没有任何「样本是否用完、是否重复」的校验。

现版本：先按 lognormal（`sigma=0`，即等分）算每客户端样本数，再逐客户端按 `cls_priors` 从各类池抽样，类池空则从候选中剔除，最后 `assert 已分配 == 总数`。

| 项 | 原包 | 现在 |
|---|---|---|
| 每客户端样本数 | 近似相等（lognormal sigma=0） | 相同（等分） |
| 类别先验 | Dirichlet α=0.3 | 相同 |
| 是否无放回 | 是（但无校验） | 是（有断言校验） |
| 样本级划分结果 | A | 不同（B） |
| 死循环风险 | 有 | 无 |

**判定**：属于「参考实现调整」。统计特性（客户端数、α、每客户端类分布）保持一致，但**具体哪些样本属于哪个客户端与原包不同**。所以：组内对照有效；与原文/原包的数字对比无效。

### 3.2 验证集 20% 分层切分（`_split_train_validation`）

原包没有验证集，客户端用全部本地数据训练。现版本 `--validation_ratio 0.2` 时，从训练集按类分层再切 20% 出来，训练数据 **直接少 20%**。

- 5 客户端 smoke：每客户端训练 8000、验证 2000（`docs/archive/11_配对聚合检查_2026-11-04.md` 记录）。
- 20 客户端 5 epoch / 10 轮：所有服务器实验都传了 `--validation_ratio 0.2`。

**判定**：这是**最容易被质疑「和论文对不上」的一处**，不是造假，但必须主动说明。影响范围：

| 用途 | 是否受污染 |
|---|---|
| all vs base 配对比较（同验证集、同训练量） | 不受，两边都少 20% |
| 绝对值与论文/原始包对比 | 受影响，不能逐点比 |
| KL-收益分析（依赖验证集） | 本来就必须有验证集，这是前置条件，不是污染 |

### 3.3 2-hop 候选的「圆心」变了

原包 `select_neighbors_two`：

- 候选集 = `get_k_hop_neighbors(client_idx, k)`，即**以目标客户端为圆心**取 k 跳；
- k=2 时递归实现返回的恰好是「距离 client 为 2」的节点集合（距离 1 被减掉）。

现版本：

- 候选集 = `get_k_hop_neighbors(neigh1_id, k)`，**以每个一跳邻居为圆心**；
- `get_k_hop_neighbors` 重写为 `single_source_shortest_path_length` 取距离 `1..k`，不再递归叠加。

叠加后面的过滤条件 `neigh2_id not in adj(neigh1_id)`，两端实际留下来的都是「距离 neigh1 恰好 2」的节点。所以：

| 版本 | 有效候选 |
|---|---|
| 原包 | 距离 **client** 恰好 2，且不是 neigh1 的邻居 |
| 现在 | 距离 **neigh1** 恰好 2 |

在 20 节点、每节点 10 度左右的 ring 图上，这两个集合**不一样**（能差出 1~3 个节点）。新版语义更贴合「给 neigh1 找补充伙伴」的本意，但它确实改变了多跳搜索的行为。

**判定**：参考实现调整。复现论文级别的多跳曲线时，必须声明用哪一版语义。

### 3.4 邻居数上限 `max_neighbors=2`

原包没有上限：`select_neighbors` 选中的一跳邻居 + `select_neighbors_two` 补的二跳邻居，全部参与聚合。现版本每轮结束前 `_cap_selected_neighbors` 按 KL 距离升序截断到 `max_neighbors` 个。

所有有效实验都传了 `--max_neighbors 2`。**这意味着「hops=2」的实验里，每轮真实协作邻居只有 2 个**——多跳提供的是「候选池扩大」，不是「聚合人数变多」。

**判定**：新方法实验开关，属于实验设计选择，不是 bug。但写论文时不能说「多跳带来更多邻居聚合」，只能说「多跳扩大候选、再由 KL 截断」。

### 3.5 聚合范围开关 `aggregate_scope` / 自权重 `self_weight_scale`

`_aggregate_func` 改成：

```text
total_num = local_num * self_scale + Σ neighbor_num
W = (local_num * self_scale) / total_num
layers: scope == 'base' 时跳过 classifier 层（linear.weight / linear.bias）
```

- `self_weight_scale=1.0`（默认）：公式与原包**逐项等价**。
- `aggregate_scope='all'`（默认）：遍历全部 state_dict 键，与原包**等价**。
- `aggregate_scope='base'`：**新增行为**，只聚合 backbone，分类头保留本地。

分类头识别用 `['head', 'linear']` 匹配参数名。`customized_resnet18` 的头部是 `self.linear`，key 为 `linear.weight/linear.bias`，**能正确命中**；这也解释了为什么 `agg-base` 分支确实保住了 head（配对检查中 base-only 分支 head 与聚合前最大差 0.0，all 分支最大差 0.03~0.12）。

**判定**：`all` 路径与原包等价，`base` 是新实验条件。核心结论（head 平均的即时破坏）就建立在这个开关上，检查通过。

### 3.6 默认参数与原包不同

`main_ProToDFL.py` 改了几个默认值：`gpu` 从 3 改 0，`data_dir`/`output_dir` 改为本机路径，新增 `--tag` 会拼进 run_id。

**风险点**：如果只看命令不带全参数，可能误以为跑的是原包配置。实际每个实验参数都写进了 `docs/02` 的命令行，且 run_id 里带 `tag`，可以反查。以后新增实验建议一律写全参数。

## 4. 不改变实验数字的改动

| 改动 | 说明 |
|---|---|
| `dataset[7]` 取 `class_num` | 返回元组从 8 元素扩到 10 元素，`[-1]` 会变成验证集，所以改成固定下标；原包 `[-1]` 就是第 8 个元素，等价 |
| `initial_model_sha256` / `data_split_sha256` | 纯记录，写进 `*_comm.json`，不参与计算 |
| `_proto_access_count` / `comm_sizes` | 只做字节与访问次数统计，在 `select_neighbors` 后累加，不影响选择结果 |
| `_save_round_models` | 仅在 `--save_models_round <n>` 时触发，默认 `-1` 不保存 |
| `oracle_mode` | 默认 0；只有 `--oracle_mode` 打开时才走 `_select_oracle_neighbors`。`docs/09` 第 3 节的 oracle 实验显式打开过，且已在文中标明「不是可实现方法」 |
| `draw_and_save_graphs` 路径 | 从硬编码绝对路径改成 `output_dir` 下，只影响图存哪里 |
| 随机拓扑防死循环 | 只在 `cs` 不是 `ring`/`full` 时生效，且失败退化为 ring；20 客户端 ring 实验不经过这条分支 |
| `NetworkTopology` 度数上限 | `n=20` 时 `min(10, 19)=10`，与原逻辑一致 |

## 5. 对现有结论的影响判定

### 5.1 站得住的

1. **agg-all 的即时破坏**：来自同一快照的离线重放，两条分支共享参数，只改是否平均 head；`_aggregate_func` 的 `all` 路径已验证与原包等价。代码改动不影响这个结论。
2. **all vs base 的多轮配对**：同一 seed 内 `initial_model_sha256`、`data_split_sha256`、通信字节、定向链接数完全一致，唯一差异是聚合范围。配对有效。
3. **KL-收益分布**：只依赖快照 + 验证集，不依赖训练代码路径；`get_k_hop_neighbors` 的改动影响的是「候选怎么来」，KL 本身的计算没动。

### 5.2 不能说的

1. **不能说「复现了 ProToDFL 论文的准确率」**。划分算法、验证集、2-hop 语义、邻居上限四处不同。
2. **不能说「多跳聚合更多邻居带来收益」**。`max_neighbors=2` 把聚合人数钉死了。
3. **不能跨代码时点比较绝对值**。早期实验（无 `data_split_sha256` 记录）跑在哪个版本已经无法回溯，只能作为「现象观察」，不能与现在的数字拼表。

### 5.3 一个必须承认的空白

项目没有 git，早期实验（E1–E3 的本地快照、1 epoch 试点）**无法证明跑在哪一版代码上**。补救手段是现版本已把两个 SHA 写进 `*_comm.json`；从现在起每个正式结果都能自证。

## 6. 以后怎么防止「改坏了还不知道」

1. 每次正式实验，把 `initial_model_sha256` + `data_split_sha256` 抄进 `docs/02` 的运行记录（现在已有字段，只是没抄）。
2. 改核心算法文件后，先跑一次 `diff_vs_original.py`，确认改动清单与预期一致。
3. 任何「只改一个变量」的对照，先用 `paired_aggregation_check.py` 在同一快照上离线验证一遍参数一致性，再上服务器训练。
4. 换代码路径（比如改 2-hop 语义）必须新开 RUN 编号，不与旧结果合并成一张表。

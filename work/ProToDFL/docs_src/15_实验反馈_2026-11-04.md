## 二、三项一致性核对

### 2.1 数据划分、初始模型与测试索引

每个快照的 `metadata.json` 保存两个 SHA-256：`initial_model_sha256` 对应初始全局模型，`data_split_sha256` 对应每个客户端训练、验证、测试三个数据加载器的索引。后者同时覆盖三类索引。

十轮实验的取值（前 12 位）：

| 分支 | initial_model_sha256 | data_split_sha256 |
|---|---|---|
| all-s0 / base-s0 | 7a999e03c6c5 | 5700766d1064 |
| all-s1 / base-s1 | d3dee0479e8f | 28e22cf82f2b |
| all-s2 / base-s2 | 0106f747af51 | 67ae064599f5 |

同一随机种子下，两条分支的两项取值完全相同；不同种子之间不同。三轮实验同样满足。因此两条分支共享同一份划分与同一批测试样本，可直接复现。

### 2.2 邻居与聚合权重

链接总数相同不能证明邻居相同，因此执行了逐客户端比对：

```
seed0  client-level neighbors identical: True  (diff=0)
seed1  client-level neighbors identical: True  (diff=0)
seed2  client-level neighbors identical: True  (diff=0)
```

比对对象为 `checks/server-paired/*.csv` 中 `neighbors` 列，覆盖 3 个种子、每个 20 个客户端。两条分支在每个客户端上的邻居集合完全一致。聚合权重由同一份样本数表与同一段代码计算，逐项相同。

### 2.3 分类头是否仅在本地训练

配对检查保存了三个校验量：

| 校验量 | 实测值 | 含义 |
|---|---|---|
| `base_max_abs_diff` | 0.0 | 两条分支聚合后的 backbone 参数完全相同 |
| `base_head_max_abs_diff_vs_pre` | 0.0 | base 分支分类头与聚合前完全相同 |
| `all_head_max_abs_diff_vs_pre` | 0.0384 | all 分支分类头确有改动，说明开关生效 |

对应实现上，`agg-base` 在聚合循环中对分类头参数跳过，权重公式、聚合顺序、自身权重缩放均未改动；分类头仍由本地训练更新，未冻结，也未改变本地训练次数。参数、代码、权重三层证据一致。

## 四、自主补充实验

以下三项为老师任务之外自行开展的检查，结果供参考。

### 4.1 KL 距离的分组效果

将 187 对有效结果按 KL 距离四等分：

| KL 分组 | 平均准确率变化 | 变差比例 |
|---|---|---|
| 最低 25% | +0.93 pp | 48.9% |
| 25%–50% | +0.80 pp | 61.7% |
| 50%–75% | −4.27 pp | 76.6% |
| 最高 25% | −1.92 pp | 73.9% |

低 KL 区间平均为正收益，四组均值依次为 +0.93、+0.80、−4.27、−1.92 pp；第 1 组与第 3 组相差 5.2 pp，与第 4 组相差 2.85 pp，前者与论文消融中 5.15 pp 的量级一致。说明 KL 在排除不相似邻居这一层面有效，在精确排序层面不足：全样本上 Spearman 相关系数仅 −0.2588，按 KL 选取最优邻居与事后最优选择相差 5.85 pp。

### 4.2 分类头的退化程度

以验证集输出类别数判断分类头是否退化。数据本身没有单类别客户端，但训练不足时退化普遍：

- 1 个本地 epoch 时，380 对结果中 347 对的目标分类头只输出单一类别；
- 5 个本地 epoch 时，每 20 个客户端中退化的有 1 个、6 个、5 个（对应种子 0、1、2）。

退化程度与训练量强相关，说明全参数聚合的破坏在弱模型上被显著放大。

### 4.3 十轮延长的结果

将通信轮从 3 轮延长至 10 轮，三个种子的末轮均值：

| 分支 | 末轮准确率 |
|---|---|
| 全部参数聚合 | 0.6172 |
| 仅聚合 backbone | 0.6261 |

差值 +0.89 pp，标准差 1.40 pp；三个种子分别为 +1.87、+1.50、−0.72 pp。差值随轮数不单调：前期仅聚合 backbone 领先，中期收窄至 ±0.005，后期在 0 至 +0.02 之间波动。

这一结果与第三节的即时破坏并不矛盾：单次聚合平均造成损失，后续本地训练会修复其中一部分。但三个种子里有一次反向，标准差（1.40 pp）大于均值差，因此只能说方向一致、幅度在种子噪声内；既不能概括为长期有效，也不能概括为长期无效。要判断长期趋势，应补种子而不是继续延长轮次。

### 4.4 原型更新时机的影响

原实现仅在首轮计算并写回客户端原型，此后各轮虽重新计算，但未覆盖已存的值。选邻与拓扑调整因此始终基于初始模型产生的原型。为量化这一差异，新增 `--proto_update_each` 开关，默认值 0 保持原行为，置 1 时每轮刷新。

对照条件为同一份代码、同一组参数、同一随机种子，仅切换该开关。冻结分支沿用既有 `srv20-e5-r10-*` 的结果，刷新分支以 `p1-r10-*` 标记重新运行，两组各覆盖三个种子、两种聚合范围。

末轮准确率：

| 种子 | 分支 | 原型冻结 | 每轮刷新 | 差值 |
|---|---|---|---|---|
| 0 | 全部参数 | 0.6682 | 0.6760 | +0.78 |
| 0 | 仅 backbone | 0.6869 | 0.6802 | −0.67 |
| 1 | 全部参数 | 0.5885 | 0.5858 | −0.27 |
| 1 | 仅 backbone | 0.6036 | 0.6033 | −0.03 |
| 2 | 全部参数 | 0.5949 | 0.5938 | −0.11 |
| 2 | 仅 backbone | 0.5878 | 0.6153 | +2.75 |
| 均值 | 全部参数 | 0.6172 | 0.6185 | +0.13 |
| 均值 | 仅 backbone | 0.6261 | 0.6329 | +0.68 |

六个配对中五个差值在 ±0.8 pp 以内，仅种子 2 的 backbone 分支达 +2.75 pp。组内标准差为 4.0 至 5.4 pp，均高于刷新带来的均值变化。

过程层面差异确实存在。以种子 0 的全部参数分支为例，冻结组的拓扑调整记录为 3 次，刷新组为 11 次；两组第 0 轮完全一致（0.5400），自第 2 轮起路径分离，单轮最大偏离 1.2 pp。

结论：该实现差异改变邻居演化的过程，但不改变末轮精度。其影响幅度低于种子间波动，既有 all 与 base 的比较结论不受影响。若论文保留"每轮更新原型"的表述，需注明实际实现为首轮更新后冻结，或改用刷新分支的数据。

## 五、实现偏差与待办

### 5.1 四处实现偏差

四项均为原始交接包既有实现。第一、二、四项只涉及表述、统计口径与命名，本次不改动；第三项涉及算法行为，本轮补充了一个可选开关，默认值保持原有行为不变。

| 项 | 实际情况 | 来源 | 影响 |
|---|---|---|---|
| 通信轮命名 | 循环为 `range(comm_round+1)`，参数值比实际聚合次数少 1 | 原包循环写法 | 仅影响文字表述，不影响实验 |
| 原型通信量 | 统计按每邻居 256 计，实际向量为 512 维 | 原包写死的常量 | 只影响通信量数字，不影响准确率 |
| 原型更新时机 | 仅在 `round == 0` 写回一次，之后冻结；本轮新增 `--proto_update_each`，默认 0 保持原行为，置 1 则每轮刷新 | 原包实现，本轮加开关 | 影响选邻所用特征的时效性；对照实验见 4.4 节，均值差 +0.41 pp、个别种子达 +2.75 pp，仍低于组内标准差 |
| 动量参数 | `--momentum` 为优化器动量（本轮为 0），`--momentums` 为原型 EMA 系数（0.5） | 原包参数命名 | 仅易混淆，不改变行为 |

通信统计口径另有说明：现有 `num_comm_params` 统计模型非零参数个数与原型交换量，不含控制消息、多跳转发与序列化开销，属于有效负载量，不能视为实测网络成本。按第二轮指导，后续报告应按稠密张量实际发送元素数 × 每元素字节数 × 交换次数重新统计；本文表格沿用非零参数计数，只为与既有日志一致，不作为传输字节。

### 6.2 通信统计口径

统计字段为 `sum_comm_params`，按客户端累加、每轮汇总一次。计入的部分：

| 项 | 计法 | 每轮每客户端 |
|---|---|---|
| 模型上传 | `count_communication_params` 统计参数字典中的非零元素个数 | 1 次 |
| 模型下载 | 同上，全局模型下发时统计 | 1 次 |
| 原型交换 | 按写死常量 `256 × 邻居数` 计 | 邻居为 2 时计 512 |

尺寸参照：模型为 ResNet-18（CIFAR-10 版），两条分支结构相同；原型为 512 维向量。未计入的部分包括控制消息、stop-and-wait 的等待与重传、多跳转发的中间节点开销、序列化与协议开销。因此该数字是有效负载量，不是实测带宽消耗，跨实现比较需先统一口径。

本轮该字段输出到 `logger.info`，未落在 `console/` 的重定向文件里（那里只有进度条），因此没有可直接引用的逐轮数值。以上按代码定义复算，未作估算填充。

### 6.3 原型的计算与更新方式

原型的计算在本地训练循环内完成，每个 batch 执行一次：

```python
rep = model.base(x)                                    # 特征表示，512 维
running_mean = torch.mean(rep, dim=0)                  # 当前 batch 的表示均值
old_running_mean = (1 - m) * old_running_mean + m * running_mean   # EMA，m = 0.5
```

`m` 取自 `--momentums`，本轮为 0.5；初始值为 `torch.zeros_like(rep[0])`，从零向量开始累积。原型的用途是选邻：服务端用各客户端原型计算 KL 距离，据此筛选候选邻居并调整拓扑。

更新时机存在一处实现差异：客户端对象每轮都会带回新的 `running_mean`，但服务端只在 `round == 0` 时写回全局原型，之后各轮算出的值没有覆盖已存的值。因此"每轮重新计算"成立，"每轮生效"不成立。4.4 节用 `--proto_update_each` 对此做了对照。
